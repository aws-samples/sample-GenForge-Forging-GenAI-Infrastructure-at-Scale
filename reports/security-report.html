Executive Summary

Risk Assessment

Risk Level: MODERATE — No critical vulnerabilities found, but 12 high-severity issues require attention before production deployment. The platform has a strong security foundation (OIDC auth, KMS encryption, removal policies, private repos) but needs hardening in IAM policies, authentication configuration, and input validation.

Key Concerns:

  • Authentication & Authorization (3 HIGH): Guest auth enabled in production config, allow-all permission policy grants unrestricted access to infrastructure provisioning
  • IAM Over-Privilege (4 HIGH): Multiple CDK stacks use AmazonSageMakerFullAccess managed policy and iam:PassRole with resources=["*"]
  • Network Exposure (2 HIGH): OpenSearch collection allows public access; MLflow ALB exposes HTTP traffic to internet
  • Supply Chain (2 HIGH): CDK CLI installed with @latest across all 16 workflows; --require-approval never bypasses change review
  • Script Injection (1 HIGH): VPC destroy workflow interpolates user input directly in bash run block

Strengths: All S3 buckets enforce SSL and block public access. All workflows use OIDC (no long-lived credentials). All KMS keys have rotation enabled. All templates create private GitHub repos. All component names are pattern-validated. No hardcoded secrets detected.

HIGH GitHub Actions templates/foundation/vpc/skeleton/.github/workflows/destroy.yml:27
Script injection via github.event.inputs.confirm in run block
Workflow directly interpolates '${{ github.event.inputs.confirm }}' in a bash run block. Malicious input containing shell metacharacters could execute arbitrary commands.
▶ Show Remediation
Use an environment variable instead: set 'env: CONFIRM: ${{ github.event.inputs.confirm }}' and reference as $CONFIRM in run block. Or remove the redundant shell validation since job-level 'if' already gates execution.
HIGH Supply Chain All 16 workflow files
CDK CLI installed with @latest tag across all workflows
Every deploy and destroy workflow uses 'npm install -g aws-cdk@latest'. Different runs may install different CDK versions, causing non-reproducible builds. A compromised CDK release would be automatically pulled into all deployments.
▶ Show Remediation
Pin to a specific CDK version (e.g., 'npm install -g aws-cdk@2.170.0') matching the version in requirements.txt. Update deliberately through PRs.
HIGH GitHub Actions All 8 deploy workflows
--require-approval never without environment protection
All 8 deploy workflows use 'cdk deploy --require-approval never'. 7 of 8 do NOT set the 'environment' property at the job level, meaning GitHub environment protection rules cannot gate deployments. Security-sensitive IAM changes deploy without human review.
▶ Show Remediation
Add 'environment' property to all deploy jobs. Configure required reviewers for staging/prod in GitHub. Use '--require-approval broadening' for non-dev environments.
